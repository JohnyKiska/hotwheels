# Release lineage rules

**Статус:** зафиксированные правила идентичности и проектное направление для будущих связей между выпусками.
**Источник:** решения и аудит из PR #78, 2026-11-04.
**Реализация:** отдельная таблица Release-to-Release и API/UI пока не реализованы.

## Подтверждённые правила

1. Один `Casting` может иметь несколько `Release`.
2. Выпуск каждого официального каталожного года является отдельным `Release`, даже если модель внешне повторяется.
3. TH, STH и Chase являются характеристиками конкретного `Release`, а не самостоятельными `Casting`.
4. Повторное появление модели, перекраска или специальное исполнение не должны автоматически объединять разные `Release`.
5. Совпадение названия, SKU или похожего описания само по себе не доказывает родство выпусков.
6. Существующая связь `Casting → Releases` описывает принадлежность выпусков к базовой конструкции. Она не заменяет отношение одного `Release` к другому.

## Предлагаемое расширение

В будущем спроектировать универсальную связь `Release ↔ Release` с полями:
- `release_id`;
- `related_release_id`;
- `relationship_type`;
- `note`;
- `status`;
- provenance / Evidence и история решения.

Предварительные типы отношений:
- `recolor` — перекраска;
- `reissue` — повторный выпуск;
- `special_variant` — специальное исполнение;
- `related_release` — иное подтверждённое родство.

Направленность и симметричность связей, допустимые сочетания типов, ограничения и правила отображения цепочек требуют отдельного проектирования.

## Обязательные требования

- Не создавать lineage-связь автоматически только по сходству названий.
- Сохранять источник и Evidence, подтверждающие конкретное отношение.
- Не считать предполагаемое родство подтверждённым фактом.
- Поддерживать ручную проверку и пересмотр решения с audit trail.
- Не менять идентичность `Casting` или `Release` при добавлении связи.
- До реализации подготовить тесты на цепочку recolor между годами, отдельность Mainline/TH/STH Release одного Casting и отсутствие автоматической связи при совпадении только названия.

## Текущее состояние интеграции

В текущей модели есть `Casting`, `Release` и связи `Casting → Releases`. Универсальная таблица отношений между двумя `Release` не обнаружена и не входит в текущую миграционную цепочку. Этот документ фиксирует требования, а не заявляет о готовой функциональности.
