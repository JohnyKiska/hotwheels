# eBay Integration

Статус на 2026-11-19: локальная реализация и тестирование завершены; публичный Sandbox endpoint не развёрнут, Production отключён. Этот документ описывает подтверждённое локальное состояние, а не успешную доставку реальных уведомлений eBay.

## 1. Общая архитектура

Интеграция изолирует eBay OAuth, Browse API и Account Deletion Notifications от канонического каталога Hot Wheels:

- `backend/app/ebay_notifications_api.py` содержит OAuth token/public key helpers и GET/POST обработчики account deletion.
- `backend/app/main.py` регистрирует router с префиксом `/api/v1/integrations/ebay`.
- eBay-данные хранятся в отдельных моделях и таблицах `ebay_sellers`, `ebay_listings` и `ebay_notifications`.
- Browse API проверялся отдельными Sandbox-скриптами. Это не импортёр каталога и не подтверждение полноты или актуальности рыночных предложений.
- Секреты читаются серверной конфигурацией из переменных окружения; они не должны попадать в документацию, репозиторий или браузер.

FastAPI не применяет Alembic автоматически при импорте приложения. Windows startup script явно выполняет `alembic upgrade head` до запуска Uvicorn; при других способах развёртывания миграцией нужно управлять отдельно.

## 3. OAuth Client Credentials Grant и Browse API

Для Browse API используется OAuth 2.0 Client Credentials Grant с scope `https://api.ebay.com/oauth/api_scope`. Он выдаёт Application Access Token и не требует пользовательского eBay login или согласия пользователя.

Sandbox-запрос токена выполняется к `https://api.sandbox.ebay.com/identity/v1/oauth2/token`; Production host выбирается только при соответствующем окружении. Browse API проверялся с Application Access Token, в том числе через поиск объявлений и получение сведений об item. Для Sandbox-запросов использовался marketplace `EBAY_US`.

Проверка Browse API подтверждает доступность протестированных запросов, но не гарантирует, что Sandbox содержит реалистичные объявления или что Browse API предоставляет sold/completed listings. Возможность и условия Marketplace Insights API, включая данные для оценки рыночной стоимости, требуют отдельного подтверждения.

## 4. Модели EbaySeller, EbayListing и EbayNotification

Модели находятся в `backend/app/models.py` и не связаны с сущностями общего Hot Wheels каталога.

- **`EbaySeller`**: eBay user ID, username, display name, профиль, состояние active/anonymized и время удаления данных.
- **`EbayListing`**: eBay item ID, nullable-ссылка на продавца (`ON DELETE SET NULL`), title/URL, цена, валюта, condition, состояние объявления и временные метки наблюдения/анонимизации.
- **`EbayNotification`**: уникальный notification ID, topic, event/publish/receive/process timestamps, статус, признак валидной подписи, число попыток, SHA-256 payload и обобщённая ошибка. Полный payload и `eiasToken` в модели не сохраняются.

Ограничения моделей проверяют допустимые статусы, неотрицательные значения и обязательные временные метки для обработанных или обезличенных записей.

## 5. Account Deletion Notifications

Обработчики доступны по `/api/v1/integrations/ebay/account-deletion`:

- `GET` — проверка endpoint через challenge;
- `POST` — проверка подписи и обработка уведомления.

POST сначала разбирает структуру и проверяет подпись, и только после успешной проверки обращается к БД. Темы, не относящиеся к `ACCOUNT_DELETION`, сохраняются как `ignored` и подтверждаются без изменения записей каталога.

Обработчик не удаляет общие данные Hot Wheels. Он работает только с eBay-таблицами; в тестовой БД `Casting` и `Release` не изменялись.

## 6. GET challenge validation

GET принимает обязательный непустой `challenge_code`. Для ответа требуются серверные `HW_EBAY_DELETION_VERIFICATION_TOKEN` и `HW_EBAY_DELETION_ENDPOINT_URL`. Токен проверяется на длину 32–80 символов и допустимый набор букв, цифр, `_` и `-`.

`challengeResponse` вычисляется как lowercase hex SHA-256 от UTF-8 конкатенации:

`challenge_code + verification_token + endpoint_url`

Успешный ответ — JSON `{"challengeResponse": "..."}`. Локально проверено совпадение результата с независимым вычислением; неверные параметры и отсутствующая конфигурация также проверены. Публичная регистрация endpoint и вызов eBay не выполнялись.

## 7. POST notification processing

POST требует заголовок `X-EBAY-SIGNATURE`. Невалидный JSON/формат отклоняется до записи в БД. Подписанный notification ID, topic и временные метки используются для минимальной записи аудита.

Для темы account deletion обработчик находит продавца по `userId`, обезличивает найденную eBay-запись продавца и связанные объявления, затем отмечает notification как `processed`. Неизвестный продавец не приводит к изменению других записей. Успешная обработка, включая игнорируемую стороннюю тему, отвечает HTTP 204.

## 8. ECDSA-подписи, публичные ключи и кэши

Подпись проверяется до любых изменений БД. Обработчик декодирует `X-EBAY-SIGNATURE`, проверяет алгоритм ECDSA и digest, получает ключ по `kid` через eBay Commerce Notifications public-key endpoint и проверяет подпись канонически сериализованного JSON.

Поддерживаются SHA-1, SHA-256, SHA-384 и SHA-512 при соответствии digest в заголовке и ответе ключевого endpoint. Ключ может быть передан PEM или DER.

OAuth access-token cache и public-key cache разделены по окружениям `sandbox` и `production`. Access token обновляется с запасом до истечения срока; публичный ключ кэшируется на один час. Это разделение проверялось изолированными локальными тестами; Production keyset и Production API не использовались.

## 9. Идемпотентность, повторные попытки и ошибки

`notificationId` уникален. Для сравнения повторов вычисляется SHA-256 нормализованного JSON, из которого исключён изменяемый `publishAttemptCount`. Повтор с тем же ID и тем же payload после `processed`/`ignored` получает 204; повторное использование ID с другим payload получает 409.

Записи `failed`/`received` допускают повторную обработку. Ошибка транзакции приводит к rollback, после чего сохраняется запись с `failed` и обобщённым `last_error`; API отвечает 503, чтобы доставка могла быть повторена. Проверена и гонка уникального ID: существующая запись сверяется и по хешу, и по статусу, а не подтверждается безусловно.

Отсутствующая или неправильная подпись отклоняется с 412; некорректная структура — с 400; недоступность проверки ключа/токена и ошибки обработки требуют повторной доставки. Содержимое уведомления и персональные данные не включаются в текст ошибки.

## 10. Обезличивание персональных данных продавца

При account deletion для найденного продавца очищаются `ebay_user_id`, `username`, `display_name` и `profile_url`; запись переводится в `anonymized` и получает `deleted_at`.

В связанных объявлениях очищаются `title` и `item_url`; статус становится `anonymized`, записывается `anonymized_at`. Записи не удаляются, а общие сущности каталога не затрагиваются. Поля `eiasToken` не сохраняются. Реальные уведомления от eBay не поступали; поведение проверялось только на синтетических данных.

## 11. Alembic migration `20261119_ebay_notifications`

`backend/migrations/versions/20261119_ebay_notifications.py` создаёт три отдельные eBay-таблицы. Перед созданием она фиксирует, какие таблицы уже существовали, в служебной таблице состояния. Маркер владельца содержит ID этой ревизии; чужая или несовместимая служебная таблица отклоняется без автоматического исправления. Повторный upgrade собственной незавершённой миграции сохраняет уже записанные флаги.

Downgrade удаляет только eBay-таблицы, созданные этой миграцией, и только её собственную служебную таблицу. Ранее существовавшие eBay-таблицы и их данные сохраняются. **Важно:** downgrade удалит созданные миграцией таблицы вместе со всеми данными, добавленными в них после upgrade. Не выполняйте downgrade, если эти данные нужно сохранить.

Миграция проверена только на временных SQLite-БД; основная `DATABASE/catalog.db` не открывалась и не изменялась. Семь миграционных тестов прошли.

## 14. Ограничения и следующие этапы

1. Для публичного тестирования нужен публичный HTTPS endpoint; у проекта пока нет домена и хостинга. До их появления Sandbox-доставка через eBay не проверена.
2. Перед включением Production необходимо выполнить требования eBay к Account Deletion Notifications либо получить официальное освобождение (exemption). Production остаётся отключённым до подтверждения этого условия.
3. После развёртывания публичного HTTPS endpoint нужно зарегистрировать его в eBay Developer Portal и провести end-to-end Sandbox-тесты реальной тестовой доставкой.
4. Browse API не гарантирует доступ к sold/completed listings. Marketplace Insights API и получение данных, пригодных для оценки рыночной стоимости, требуют отдельного подтверждения.
5. Миграция не исправляет автоматически частично существующую несовместимую схему; перед миграцией/откатом целевой БД нужны отдельная проверка и резервная копия.
6. Локальная криптографическая и HTTP-проверка не подтверждает публичную TLS-конфигурацию, регистрацию endpoint или доставку eBay.
