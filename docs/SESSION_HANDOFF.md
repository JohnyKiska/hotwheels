- Перед новым шагом проверять актуальные main, PR и CI.

- Не менять `main` напрямую; все изменения через отдельную ветку и PR.

## Безопасность и рабочий процесс

- Не изменять main напрямую. Использовать отдельную ветку и Pull Request.
- Не редактировать и не мигрировать production collection.json без отдельного согласования.
- Не записывать данные в рабочую БД на этапе аудита/проектирования.
- Все первые импортные проверки проводить на отдельной тестовой БД.
- Не удалять тестовые записи и не очищать тестовую БД без разрешения.
- Не объединять совпадения между разными исходными файлами автоматически.
- Сохранять происхождение значений и свидетельства; существенные конфликты отправлять на ручную проверку.
- Не считать функцию проверенной, пока не выполнены соответствующие автоматические и/или ручные тесты.
