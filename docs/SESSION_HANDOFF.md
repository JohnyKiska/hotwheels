### Импортеры: Mainline и All Hot Wheels preview parsers в Draft PR #74

Пользователь 2026-10-30 подтвердил семейство специализированных обработчиков: Mainline первым, Premium отдельно, остальные по мере необходимости.

В Draft PR #74 (`feat/mainline-importer-preview`) добавлены:
- `backend/app/importers/mainline.py`: TSV parser под формат старого `converter.html` и parser основной таблицы Fandom yearly-list HTML.
- `POST /imports/mainline/preview` и `POST /imports/mainline/fandom-html-preview`: API endpoints без доступа к сессии БД и без записи данных.
- Для Fandom `Col.#` хранится отдельно как `collector_number`; год страницы сверяется с запрошенным годом.
- Parser- и API-тесты на синтетических примерах.
- Дубли Toy number сохраняются отдельными строками и помечаются для ручной проверки.
- В переданном наборе Fandom за 2025 год найдена строка JBC25, '85 Honda City Turbo II, Col.# 141, HW J-Imports Treasure Hunt, 5/5. Другие приложенные карточки: Raphael (2020 Character Cars), Enforcer (2015 Themed Entertainment), Mitsubishi Eclipse (2026 Fast & Furious Premium); это полезные отрицательные примеры, не Mainline.

Это первый рабочий вертикальный срез, не полный импорт. На workflow run #119 обе jobs (`pytest` и `browser-e2e`) завершились success. В том же PR добавлен `backend/app/importers/all_hot_wheels.py` и `POST /imports/all-hot-wheels/html-preview`: read-only parser индивидуальной карточки All Hot Wheels. Он извлекает SKU, название, год, категорию, special label, scale, base material, серию, Series index, `Mainline #`, доступные колёса, цвета и теги. `chase` и `treasure hunt` сохраняются как исходные метки. Синтетические parser/API-тесты добавлены. Четыре реальные страницы JBC25, GJJ06, CKJ44 и JHW68 доступны в приложенных файлах и материализованы в рабочую папку `/mnt/data/hw_import_samples`; они изучены на уровне структуры и полей, но полный запуск committed parser на этих файлах ещё нужно подтвердить. Workflow run #140 (`41079292033`) на commit `8624ea0966e847b3fc899db724fc32e495806ef5` прошёл: `pytest` — 145 passed, 8 warnings; `browser-e2e` — success.

Пока нет сопоставления с существующими Casting/Release, записи SourceRecord/Evidence и явного подтверждения импорта.

Пользователь согласовал правило годового номера Mainline: отображать `mainline_number/mainline_total` (например, `141/250`) только если оба значения подтверждены. Это отдельная пара от `series_index/series_total` (например, `5/5`). Fandom `Col.#` всегда хранится как `collector_number`. Для годовой Fandom Mainline-страницы его можно использовать также как `mainline_number`, только если текст страницы явно подтверждает диапазон нумерации Mainline. В реальном HTML за 2025 год есть утверждение «mainline is numbered 1 through 250» и пояснение, что цветовые варианты не получают новый номер; это подтверждает `mainline_total=250` для 2025 года. 440 строк таблицы включают варианты и не являются количеством Mainline. All Hot Wheels отдельно показывает `Mainline # 141` для JBC25. Для остальных лет источник итога проверять отдельно.

### Что найдено в старом инструменте

Read-only аудит показал:
- В корне репозитория есть importer.html — старый браузерный редактор collection.json с возможностью скачать изменённый JSON.
- В нём есть отдельный разбор HTML/CSV-чек-листов: строки извлекаются и выводятся как отдельный review-результат.
- Автоматического объединения найденных строк с основной базой этот сценарий не выполняет.
- Наличие importer.html не означает, что существует готовый импорт в новую backend-БД.
- В backend/app отдельного модуля импорта и подтверждённого import API при аудите не обнаружено.
- Полноценный импорт в новую БД не реализован и не тестировался.

Не делать выводов о других старых инструментах и форматах, пока они отдельно не проверены.

## Безопасность и рабочий процесс

- Не изменять main напрямую. Использовать отдельную ветку и Pull Request.
- Не редактировать и не мигрировать production collection.json без отдельного согласования.
- Не записывать данные в рабочую БД на этапе аудита/проектирования.
- Все первые импортные проверки проводить на отдельной тестовой БД.
- Не удалять тестовые записи и не очищать тестовую БД без разрешения.
- Не объединять совпадения между разными исходными файлами автоматически.
- Сохранять происхождение значений и свидетельства; существенные конфликты отправлять на ручную проверку.
- Не считать функцию проверенной, пока не выполнены соответствующие автоматические и/или ручные тесты.
