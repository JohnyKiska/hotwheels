## Сквозные правила приоритизации

1. Сначала проверить актуальное состояние и не повторять уже выполненную работу.
2. Сначала сохранять данные и корректность идентификации, затем расширять автоматизацию.
3. Импортировать только через preview и явное подтверждение; тестировать на отдельной БД.
4. Не менять production collection.json и production-БД без отдельного согласования.
5. Существенные конфликты не разрешать автоматически без достаточных свидетельств.
6. Закрывать задачу по критериям приёмки и фактическим проверкам, а не по факту написания кода.
